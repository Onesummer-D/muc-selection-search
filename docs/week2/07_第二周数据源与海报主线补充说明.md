# 第二周数据源与海报主线补充说明

## 口径更正

角色 A 第一轮共提取 100 个样本，其中 88 个是选调经验分享海报，12 个是与选调有关但不属于经验分享的公告、通知或文本内容。第二周不得把 68 张剩余海报误写成非经验数据，也不得因为 20 张 Gold 评测集而丢弃其余经验分享海报。

本周采用三层数据口径：

| 数据层 | 数量 | 作用 | 是否进入 20 样本准确率 |
|---|---:|---|---|
| 固定 Gold 评测集 | 20 张经验分享海报 | 比较抽取路线和规则修改效果 | 是，集合、Gold、SHA-256 均冻结 |
| 扩展经验海报集 | 其余 68 张经验分享海报 | 批量抽取、岗位复核和发布准备 | 否，先统计覆盖和复核状态 |
| 非经验分享材料 | 12 个文本/公告等 | 保留系统全面性，按文本/公告类型入库 | 否，不计入人物五字段海报准确率 |

## 当前数据源实现边界

截至 2026-09-21，仓库中的 `PortalClient` 能读取门户列表和详情中的 `notice_content`，并从正文 HTML 的 `<img>` 引用生成海报资产。`article_bundle.v1` 的资产枚举虽然已经允许 `attachment`，但当前采集器没有发现、下载或解析门户中的 PDF、XLS 或 XLSX 附件，也没有把附件链接写入资产台账。

`app/extraction/build_gold_v2.py` 中出现的工作簿和受控 PDF 只用于人工 Gold/样本交接，不代表已经完成学校门户附件爬取。因而 Excel/PDF 来源目前应标记为“尚未完成采集闭环”，不得在演示或台账中写成已覆盖。

## 第二周新增数据源闭环

### A 负责发现和采集

- 在门户详情 HTML 和接口返回中识别附件链接，至少覆盖 PDF、XLS、XLSX；
- 记录 `notice_id`、附件 URL、文件名、MIME、大小、下载状态和 SHA-256；
- 原始附件放在仓库外受控目录，仓库只保留脱敏 manifest、哈希和证据摘要；
- `poster`、`text`、`mixed` 和 `attachment` 的来源状态不得混写；
- 如果附件需要登录、链接失效或服务器条件不足，登记阻塞原因，不伪造下载成功；
- 完成另一台设备 LAN、认证、备份和部署任务不因附件探测而取消。

### B 负责按格式抽取和质量复核

- 88 张经验分享海报全部进入批处理范围；20 张固定 Gold 继续作为唯一准确率测试集，68 张作为扩展生产集；
- 先对 68 张扩展海报统计 `processed`、`review_required` 和 `failed`，重点复核岗位/单位字段；
- 海报使用 OCR/版面规则，纯文本使用 `html_rule`，PDF 按文本层优先、无文本层再走页面 OCR，XLS/XLSX 按工作表和行列证据读取；
- 非经验分享的 12 个材料保留来源和正文，但没有人物五字段时不得强行生成经验记录；
- 不修改 20 张 Gold、样本 SHA-256 或启用门槛，不按单个样本硬编码规则；
- 对相同错误模式提交通用规则、回归测试、字段证据和 `review_required` 队列；
- 仍以归一化口径生成 `evaluation_report_v2`，严格结果作为审计附件。

### C 负责数据模型、检索和整合

- 在不破坏 `article_bundle.v1` 的前提下，设计附件元数据的兼容承载方式；若需要新增字段或 schema 版本，先记录决策并提供迁移/回退方案；
- 将附件来源、格式和解析状态纳入管理员复核视图，`review_required` 不进入游客和普通校内用户公开检索；
- 让 PDF/XLS/XLSX 派生出的公开文本和字段证据可以被传统搜索、详情和导出使用；
- 搜索仍采用结构化字段、别名、FTS5 trigram 和 LIKE 回退，不新增 Embedding 依赖；
- 合并 A 的附件 manifest、B 的 extraction/evidence pack，补齐 88/12 数量对账、跨格式导入和权限测试。

## 本周验收门槛

1. 台账能核对 `88 经验海报 + 12 非经验材料 = 100`，不存在重复或无类型来源。
2. 固定 20 张 Gold 的样本 ID、Gold、SHA-256 与第一周一致。
3. 68 张扩展海报有批处理状态和岗位字段复核队列，不要求在没有人工 Gold 的情况下伪造准确率。
4. 至少用脱敏 PDF 和 XLSX fixture 验证附件发现、哈希、派生文本和失败状态；真实个人附件不得入 Git。
5. 没有真实附件端点、下载权限或解析资源时，输出可复核阻塞记录，保留现有门户正文和海报主链。

## 交接顺序

1. A 先提交来源分类和附件 manifest；
2. B 使用 manifest 处理海报、PDF 和表格，提交 extraction bundle/evidence pack 及复核队列；
3. C 记录接收 Commit，完成兼容导入、搜索/详情/权限回归；
4. 三人共同更新第二周验收台账，最终演示明确区分“已采集附件”和“尚未具备端点的阻塞项”。
