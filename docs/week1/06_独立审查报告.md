## P1

### P1-01 验收公式没有把证据和 Commit 或 PR 设为通过前置条件

文件和标题：`05_本周验收台账.xlsx`，三张角色验收表的“状态”列，以及 `总览` 的 P0 验收门。

影响：角色状态公式只读取实际值、指标类型、比较符、目标值和接收确认。例如 `A验收!N6` 的公式没有引用 `J6`“证据路径或链接”和 `K6`“Commit或PR”。因此实际值达到目标且接收确认为“通过”时，证据列或提交列为空也能显示“通过”，违反总体手册要求的证据可核对原则。

明确修法：状态公式必须先检查实际值、证据路径、Commit 或 PR、接收确认，任一缺失显示“缺证据”或“待接收”。同时在 `证据索引` 中要求证据 ID 与验收 ID 可回链，C 作为唯一提交者回填主台账。

### P1-02 多模态启用结论没有由评测数据强制决定，且总览漏检五字段门槛

文件和标题：`05_本周验收台账.xlsx`，`20样本评测!D12`、`H12`，`B验收!N17`，`总览!C14`。

影响：`20样本评测!H12` 根据完整记录准确率差值计算 5 个百分点门槛，这是有效的局部公式；但 `B验收` 的 B-12 状态公式并不引用 `H12`，只看人工填写的实际值和接收确认，人工填“是”即可通过。`总览!C14` 又只检查 B-01、B-10、B-11，没有检查 B-05 至 B-09 的五字段逐项准确率，也没有检查 B-12。总览可能在弱项或启用结论未达标时显示 P0 门通过。

明确修法：B-12 的状态直接引用 `20样本评测!H12`，只有数据结论与填写的启用状态一致才能通过。`总览!C14` 至少关联五字段状态、同样本完整性、耗时成本和启用结论。保留每字段分子、分母和低于 90% 的样本清单。

### P1-03 20 张评测表能防空白分母，但不能证明金标准、哈希和同一批样本有效

文件和标题：`05_本周验收台账.xlsx`，`20样本评测`；`docs/week1/02_角色B_识别抽取与评测任务书.docx`，第“20样本金标准”和“多模态对照”。

影响：当前 `COUNT` 公式会在结果列有空白时显示“样本不足”，这一点未发现假绿；但准确率公式只依赖 0/1 结果列，没有公式或校验要求金标准字段、图像 SHA-256、标注人、OCR 和多模态样本 ID 一一对应。只要手工填写 20 个结果标记，就可能得到可计算的准确率而没有可复核金标准。

明确修法：增加固定样本清单或可回链的金标准文件，要求 20 行均有匿名 ID、哈希、人工字段和标注人；两条路线必须引用同一 ID 集合。对结果列限制只能为 0 或 1，并把缺金标准、缺路线结果和样本集合不一致分别显示为阻塞状态。

### P1-04 角色提示词与 DOCX 任务书的进度文件路径不一致

文件和标题：`docs/week1/prompts/A_goal.md`、`B_goal.md`、`C_goal.md` 的“界限”和“现状与任务0”；三个角色 DOCX 的“开始前”和“最终自查”。

明确修法：选择一种路径并全量替换。建议保留提示词中的角色目录路径，将三个 DOCX、总体手册、目录说明和验收台账证据列统一为该路径，并明确 C 只把角色进度和 PR 清单回填到 canonical Excel。

### P1-05 角色任务书的公共存储命名与接口字典不一致

文件和标题：`docs/week1/04_接口与数据字典.md`，第 5 节“C的入库模型”；`docs/week1/03_角色C_数据库检索整合任务书.docx`，表“数据库”；`docs/week1/05_本周验收台账.xlsx`，C-03。

### P1-06 重试次数和请求间隔的测量口径还不够精确

文件和标题：`docs/week1/01_角色A_采集与更新任务书.docx`，表“行为实现要求”和“测试与证据”；`docs/week1/04_接口与数据字典.md`，第 1 节；`05_本周验收台账.xlsx`，A-05 至 A-07。

影响：“最多重试 3 次”可能表示初次请求后再重试三次，也可能表示总共三次尝试；“请求间隔”也没有明确按请求开始时间、结束时间还是退避等待时间计算。不同实现都可能声称满足 0.8 至 1.5 秒和三次重试，验收不可复现。

明确修法：把指标写成“初次尝试 1 次，最多额外重试 3 次，共 4 次尝试”或明确采用总尝试次数；定义相邻门户请求开始时间差，并要求日志保留时间戳、响应类别、尝试序号和最终状态。429 反向测试按该口径留存红到绿证据。

### P1-07 固定五篇样本的内容形态与 B 的 OCR 烟测口径需要拆开

文件和标题：`docs/week1/prompts/A_goal.md`，固定样本构成；`docs/week1/02_角色B_识别抽取与评测任务书.docx`，表 B2“5篇固定样本OCR烟测”；原始技术方案第 6.3 节“文本与海报分流”。

影响：A 优先交付 2 篇文本、2 篇海报和 1 篇多人或混合内容，B 却把 5 篇统一称为 OCR 烟测。文本帖应走 `html_rule`，海报才走 OCR，混合帖需要同时保留正文和海报证据。若按统一 OCR 口径验收，会把正确的文本规则路径误判为缺少 OCR。

明确修法：B2 改为“五篇固定样本抽取烟测”，分别验收文本的 `html_rule`、海报的 OCR 坐标证据、混合帖的合并证据；20 张评测继续限定为同一批海报，并单独统计 OCR 与多模态。

### P1-08 外部多模态评测缺少数据处理边界

文件和标题：`docs/week1/prompts/B_goal.md` 的“我替领导拍的板”和“任务3”；原始技术方案第 11.6 节“外部AI/Embedding服务”；`evidence/week1/README.md`。

影响：B 被允许使用多模态 API，但执行包只约束 API Key 放在 `.env`，没有写明供应商、是否上传原图、是否只传必要脱敏素材、数据保留期限和评测授权记录。`.env` 防止密钥入库，不能单独证明个人海报没有越过允许的处理边界。

明确修法：在 B 的评测报告和证据索引中记录服务商、模型版本、发送字段或素材类型、授权依据、价格日期、保留策略和脱敏检查。默认只使用合法的内部评测素材，未确认外部处理边界前不得上传原始个人海报。
