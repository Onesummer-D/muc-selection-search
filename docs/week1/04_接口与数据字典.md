# 第一周接口与数据字典

版本：1.0  
冻结时间：2026-09-17 12:00  
维护人：角色 C  
适用范围：角色 A 的采集输出、角色 B 的抽取输出、角色 C 的入库与查询

## 1. 使用规则

1. A、B、C 只通过本文定义的 JSON 文件和公共 Python 接口交换数据，不直接读取其他成员模块内部文件。
2. 字段缺失必须写 `null`，不得用常识推测。字段冲突、低置信度和无法识别统一进入 `review_required`。
3. 原始海报、真实姓名、账号、Cookie、Session、API Key、未脱敏数据库不得提交仓库。领域层可在受控数据库保留姓名、头像和原图引用，但不得进入 Git 样本或访客 DTO。
4. 修改字段、枚举或版本号必须由 C 提交独立 PR，并由 A、B 各确认一次。未合并前继续使用旧版本。
5. 所有时间使用带时区的 ISO 8601 字符串，例如 `2026-09-17T20:30:00+08:00`。

## 2. 固定枚举

### 处理状态

| 值 | 含义 | 可进入公开查询 |
|---|---|---|
| `pending` | 已登记，尚未完成当前处理步骤 | 否 |
| `processed` | 已通过结构和质量校验 | 是 |
| `review_required` | 有结果，但至少一个关键字段需要人工复核 | 可以，页面必须显示状态 |
| `failed` | 当前步骤失败并已记录原因 | 否 |

处理状态不等于发布状态。发布状态 `visibility` 统一为 `draft`、`published`、`withdrawn`。只有经过人工确认且 `visibility=published` 的记录可进入 guest 和 student/teacher 查询；`review_required` 默认只出现在 admin 复核队列和本周演示的管理员视图。任何角色都不得把 `review_required` 直接映射为已发布。

### 内容类型

`text`、`poster`、`mixed`、`unknown`

### 证据方法

`html_rule`、`ocr_rule`、`multimodal`、`manual`

### 关键字段

`cohort`、`grade`、`education`、`college`、`major`、`city`、`position_or_unit`

## 3. article_bundle.v1

A 每处理一篇文章输出一个对象，批量交付时放入数组。对应机器校验文件为 `schemas/article_bundle.v1.schema.json`。

```json
{
  "schema_version": "article_bundle.v1",
  "notice_id": "portal-12345",
  "title": "某届选调经验分享",
  "source_url": "https://example.invalid/notice/12345",
  "published_at": "2026-09-10T08:00:00+08:00",
  "content_type": "poster",
  "clean_text": null,
  "asset_refs": [
    {
      "asset_id": "portal-12345-poster-01",
      "kind": "poster",
      "local_ref": "private://portal-12345/poster-01",
      "sha256": "64位十六进制摘要"
    }
  ],
  "fetch_status": "processed",
  "failure_reason": null,
  "fetched_at": "2026-09-17T20:30:00+08:00"
}
```

`local_ref` 只用于本地交接，不得写真实绝对路径，也不得让公开接口返回。仓库内固定5篇样本只能保留脱敏文本、素材摘要和经确认可公开的派生图。

## 4. extraction_bundle.v1

B 对一篇文章输出一个对象。一篇文章可以包含多条人物记录。对应机器校验文件为 `schemas/extraction_bundle.v1.schema.json`。

```json
{
  "schema_version": "extraction_bundle.v1",
  "notice_id": "portal-12345",
  "extractor_version": "ocr-rule-0.1.0",
  "records": [
    {
      "record_key": "portal-12345-01",
      "cohort": "2026届",
      "grade": null,
      "education": "本科",
      "college": "信息学院",
      "major": "计算机科学与技术",
      "city": "成都",
      "position_or_unit": "基层岗位",
      "review_status": "review_required",
      "confidence": 0.86,
      "evidence": [
        {
          "field": "city",
          "text": "工作地点 成都",
          "method": "ocr_rule",
          "asset_id": "portal-12345-poster-01",
          "bbox": [102, 315, 386, 361]
        }
      ]
    }
  ],
  "processing_status": "review_required",
  "failure_reason": null,
  "processed_at": "2026-09-18T18:00:00+08:00"
}
```

`confidence` 范围为 0 到 1。任何关键字段缺失、证据为空、规则与模型冲突或置信度低于 B 在评测报告中确定的阈值时，`review_status` 必须为 `review_required`。

## 5. C 的入库模型

| 实体 | 主键或唯一约束 | 必须保留的关系 |
|---|---|---|
| `articles` | `notice_id` 唯一 | 一篇文章对应零到多条人物记录 |
| `assets` | `asset_id` 唯一 | 仅保存本地受限引用、摘要和派生资源引用 |
| `experience_records` | `record_key` 唯一 | 必须关联 `notice_id` |
| `evidence` | 自增主键 | 必须关联 `record_key` 和字段名 |
| `processing_events` | 自增主键 | 保存步骤、状态、时间和失败原因 |

受控数据库中的人物实体允许保留 `person_name`、`avatar_ref`、`original_asset_ref` 和 `source_sso_url`，四者均为私有字段，不进入仓库样本。重复导入同一 `notice_id` 和 `record_key` 必须更新现有记录，不得新增重复项。

### 5.1 RolePolicy 与 Presenter

| 角色 | 可见内容 | 可执行操作 |
|---|---|---|
| `guest` | 脱敏字段、证据片段、脱敏派生资源、公开来源说明 | 查询、查看公开详情 |
| `student` / `teacher` | 经 CAS/SSO 鉴权后的完整校内字段与授权资源 | 查询、查看完整详情、访问来源 SSO 链接 |
| `admin` | 完整字段、同步状态、复核队列和审计日志 | 同步、复核、发布、查看日志 |

后端必须通过 `RolePolicy` 和 `RecordPresenter`（或等价层）生成角色 DTO。访客 DTO 删除 `person_name`、`avatar_ref`、`original_asset_ref`、`local_ref` 和内部堆栈；学生/教师 DTO 只在有效会话内返回授权字段；管理员接口必须再次校验角色。查询层先过滤 `visibility=published`，管理员复核页才读取 `review_required`。禁止把原图发给访客后仅用 CSS 隐藏，受限资源 URL 不得可枚举猜测。

## 6. 第一周 Web 接口

| 方法与路径 | 用途 | 失败行为 |
|---|---|---|
| `GET /api/search` | 结构化条件与关键词查询 | 保留条件并返回可取消的限制项 |
| `POST /api/query/parse` | 把自然语言转换为白名单 QueryPlan | 模型不可用时返回关键词降级计划 |
| `POST /api/query/answer` | 基于 QueryPlan 检索 evidence pack 并返回带引用结果 | 无证据不回答；模型不可用时返回传统结果与降级说明 |
| `GET /api/records/{record_key}` | 返回公开详情与字段证据 | 不得返回原始海报路径或受限字段 |
| `GET /api/auth/me` | 返回当前角色和可用能力 | 未登录固定返回 `guest` |
| `POST /api/admin/sync` | 在本机管理员操作下启动更新 | CAS 失效时提示重新登录，查询继续可用 |
| `GET /api/admin/sync/status` | 返回本轮进度、成功数和失败数 | 每个失败项必须带 `notice_id` 和原因 |
| `GET /healthz` | 公共 HTTPS 部署健康检查 | 依赖异常时返回非 2xx 和明确组件状态 |

QueryPlan 只允许 `cohort`、`education`、`college`、`major`、`city`、`position_or_unit`、`keywords`、`page` 和 `page_size`。模型不得生成 SQL，后端必须拒绝未知字段。

Evidence pack 至少包含 `record_key`、`notice_id`、结构化条件、字段证据数组、来源 URL 和复核状态。回答只能引用检索到的证据；证据缺失时必须返回“证据不足”并给出可复核记录，禁止补全未出现的信息。

## 7. 调度与部署契约

`SyncService` 暴露一次增量同步的稳定入口，输入上次游标和当前会话，输出任务 ID、游标、成功数、失败数和状态。`Scheduler` 只负责周期配置、单实例锁和调用 `SyncService`，不得复制采集逻辑。状态统一为 `pending`、`running`、`processed`、`review_required`、`failed`；会话失效时暂停并提示重新登录，已入库查询不受影响。

9月20日23:59前必须提供公共 HTTPS 测试 URL，并验证首页、传统检索和 `/healthz`；局域网地址保留为灾备入口。部署密钥和数据库只放主机环境变量或受控存储。若公网环境客观不可用，必须作为 P0 阻塞写入 `progress/week1/C/BLOCKED.md`，不得把局域网结果登记为公网通过。
