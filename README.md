# 选调研

选调信息智能检索系统的可点击 Demo。

项目面向校园选调经验检索场景，把分散的经验帖和海报整理成可以搜索、核验、比较和导出的信息。当前仓库同时保留旧静态原型与 Flask + React/SQLite 服务端主线；服务端使用脱敏演示数据，真实门户/CAS/OCR/多模态资源按部署条件接入。

当前第二周集成基线为 `feat/week2-integration`，本地集成提交为 `f59b1c0`。服务端主线已覆盖传统搜索、详情、权限、统计、对比、四 Sheet 导出、保存搜索、隐私、历史、提醒和无痕约束；公网 HTTPS/CAS 仍必须等真实服务器、域名和学校回调配置完成后再宣称上线。

技术、视觉、认证、功能和部署决定见 [`docs/APPENDIX_G_DECISIONS.md`](docs/APPENDIX_G_DECISIONS.md)；旧 `index.html/app.js/styles.css` 只作为交互迁移基线。

## 你可以用它做什么

- 用自然语言或关键词查找案例
- 在传统搜索和 AI 搜索之间切换
- 查看系统解析出的 QueryPlan，并删除不需要的条件
- 查看结果的匹配原因、审核状态和来源入口
- 在详情页查看结构化字段与字段级证据
- 切换游客、校内用户和管理员三种演示视图
- 选择多条记录进行横向比较
- 查看当前结果的地区和学历分布
- 导出当前结果或对比记录为 CSV
- 关闭 AI，观察系统保留传统检索能力的降级路径
- 开启无痕模式，观察不写入个人历史的产品边界

## 快速运行

服务端依赖见 `requirements.txt`，前端依赖见 `frontend/package.json`。

### 启动服务端

```powershell
pip install -r requirements.txt
python -m app.web.seed data/app.db
flask --app app.web.app:create_app run --host 0.0.0.0 --port 5000
```

再执行 `cd frontend; npm install; npm run dev`，Vite 会把 `/api` 代理到 Flask。

### 直接打开

双击 `index.html` 即可进入首页。

### 使用本地 HTTP 服务

在项目根目录执行

```powershell
python -m http.server 8000
```

然后打开 <http://localhost:8000>。

## 推荐演示流程

1. 在首页点击示例查询“计算机本科，想看西部基层案例”。
2. 在结果页查看 QueryPlan、证据摘要、匹配原因和结果状态。
3. 点击一条记录的“详情”，先以游客视图查看脱敏效果，再打开“演示控制”切换校内用户视图。
4. 返回结果页，把两到三条记录加入对比台，观察岗位未提供时的明确提示。
5. 打开对比台，查看统一字段、覆盖地区和资料完整度，然后导出 CSV。
6. 打开“演示控制”关闭 AI，确认结果、详情、统计和对比仍然可用。
7. 开启无痕模式，查看页面对个人历史和推荐信号的提示。

也可以直接测试下面两组查询

```text
计算机本科，想看西部基层案例
四川 软件工程
```

当前样例数据下，第一组查询会返回 1 条同时满足学历、专业族、西部地区和基层意图的记录，第二组查询会返回四川的软件工程记录。

## 当前实现

当前 Demo 是一个浏览器内运行的单页应用。

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架、首页、结果页、对比台、我的空间、详情弹窗和演示控制面板 |
| `styles.css` | 视觉样式、组件状态和桌面端与窄屏布局 |
| `app.js` | 虚构数据、查询解析、排序、状态管理、视图渲染、对比和 CSV 导出 |
| `docs/ARCHITECTURE.md` | 当前 Demo 的实现边界和 V3 目标架构 |

核心数据位于 `app.js` 顶部的 `records` 数组。每条记录包含基本信息、来源信息、标签、匹配原因和证据片段。页面状态集中在 `state` 对象中，交互通过 `data-action` 和事件委托驱动。

## 搜索行为

当前搜索使用确定性的浏览器内存逻辑，流程大致如下

```text
输入查询
  ↓
规范化文本
  ↓
解析学历、届别、专业、地区和基层意图
  ↓
应用结构化筛选
  ↓
计算关键词与条件匹配分数
  ↓
按相关度和届别排序
  ↓
渲染结果、统计和证据摘要
```

AI 搜索在当前版本里是交互和文案层面的演示。摘要由前端模板根据当前结果计算，未调用外部模型。正式版本需要把查询理解、检索、证据打包和答案生成拆成服务端模块，具体边界见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## Demo 边界

以下内容仍属于条件式或演示边界，不能当作已上线能力

- `app.web.seed` 的 5 篇文章/7 条记录是脱敏演示样本；第一周 A 的 100 个样本按当前核对为 88 个经验分享海报和 12 个非经验分享公告/文本，台账已归档在 `evidence/week1/A/ledger/`。LAN 首页、传统搜索和 `/healthz` 截图已归档在 `evidence/week2/A/`，详情页/录屏/设备元数据仍需补齐。
- 当前采集器已读取门户正文和正文图片，但尚未完成学校门户 PDF、XLS、XLSX 附件的发现、下载和解析；第二周按 `docs/week2/07_第二周数据源与海报主线补充说明.md` 记录附件闭环，不把格式兼容误写成已采集。
- 开发角色开关只用于本地验收；生产必须由 CAS/SSO 提供 subject，不能把客户端 header 当作认证凭据。
- 海报由 CSS 生成视觉模拟。正式版本必须由服务端生成游客可见的脱敏派生文件，不能把原图发送到前端后再用 CSS 遮挡。
- 学校门户原文链接使用占位地址，当前没有接入真实数据源。
- “已核验”和“待复核”是样例状态，不代表真实审核结果。
- 保存搜索、搜索历史、站内通知和隐私设置已落 SQLite；真实 CAS、HTTPS、邮件/短信/ICS、Embedding 和聊天机器人不在本周范围。
- B 多模态结论保持“不启用”；本周评测主判定采用归一化口径，严格逐样本文件作为审计附件。

当前版本的目标是证明交互主链和架构边界，数据准确性、权限安全和服务稳定性需要在服务端版本中重新实现并测试。

## 开发约定

- `main` 分支保持可运行。
- 每项开发先对应一个 Issue 或明确任务，再创建功能分支。
- 代码改动提交前至少完成语法检查和主流程手测。
- 修改公共数据结构、权限边界、检索主链或外部服务接口前，先更新架构文档并记录决策。
- 真实账号、Cookie、API Key、未脱敏海报和个人数据不得进入仓库。
- AI 编程助手开始工作前，应先阅读本文件和 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)，只完成当前任务，不自行扩大产品范围。
